## 1. Обзор

Сайт для преподавателей. Ведёт банк вопросов по предметам: тест, соответствие, открытый, на русском и таджикском. Собирает из банка параллельные экзаменационные билеты и выдаёт их в Word вместе с ключами ответов. Те же билеты делают Telegram-бот и Telegram Mini App. Сохранённый набор можно запустить классу: ученики проходят билет в Telegram по ссылке, преподаватель видит таблицу результатов («Билеты классу», раздел 10). Для главного админа есть экзамен-кластер (книжка из 4 предметов), «Своя игра», «Подборы» (как вопросы попадают в билеты) и «Качество банка» (поиск дублей и ошибок). Готовые билеты можно править: заменять вопросы и убирать темы. Новые версии сайта рассылаются в Telegram.

| Часть | Технологии | Где живёт |
|---|---|---|
| Сайт | React 19, TypeScript, Vite 6, Tailwind 3, TanStack Query 5, supabase-js 2, lucide-react | Vercel, автодеплой при пуше в `main` |
| База, вход, файлы | Supabase: Postgres 17, Auth, Storage, Realtime | проект `ovxrgkyexuudgtqglegk`, регион ap-northeast-2 (Сеул) |
| Сервер | Supabase Edge Functions (Deno), pg_cron (рассылка «Что нового») | `supabase/functions/*` |
| Word | `docx` 9, `jszip`, `file-saver` | браузер и Edge Functions |
| Excel | `read-excel-file`, `write-excel-file` | импорт, выгрузка итогов игры |

Репозиторий: github.com/nodir2511/testgenerator. В `main` пушат параллельно, в том числе другие сессии ИИ.

## 3. Роли и права

`profiles.role` ∈ `user` | `subject_teacher` | `subject_admin` | `admin`; флаг `profiles.is_owner` (главный админ, только вместе с `admin`).

| Роль | Подпись | Ранг `my_rank()` | Вопросы | Вкладки сверх общих |
|---|---|---|---|---|
| user | Преподаватель | 1 | читает все неудалённые | — |
| subject_teacher | Преподаватель по предметам | 1 | только свои предметы | — |
| subject_admin | Администратор по предметам | 2 | свои предметы, правит их, видит удалённые | Предметы и темы, Массовый импорт, Качество банка (только свои предметы) |
| admin | Администратор | 3 | все, включая удалённые | + Пользователи, Статистика, Корзина |
| admin + is_owner | Главный админ | 4 | все | + Экзамен-кластер, Своя игра, Подборы; один удаляет созданные наборы билетов |

Отдельная роль **game_teacher** («Учитель игры», ранг 1, только главный админ назначает): сайт показывает ей один раздел «Игры» (`isGameOnly` в `App.tsx`), банк вопросов закрыт RLS (`can_view_subject` её не пускает). Занятия по «Приёму пациента» ведут game_teacher и admin (`is_clinic_teacher()`).

Общие вкладки: Банк вопросов, Генератор, Сохранённые билеты, Что нового.

- В коде (`useAuth`): `isAdmin` (role=admin), `isOwner`, `isStaff` (admin или subject_admin), `subjectIds` (назначенные предметы для ролей «по предметам», иначе `null`), `canManage(subjectId)`.
- Предметы назначает и снимает только главный админ (`user_subjects`).
- Роль меняет только админ; триггеры `prevent_role_escalation`, `prevent_owner_escalation`, `protect_profile_fields` не дают поднять себе права.
- Регистрация закрыта: `guard_signup` на `auth.users` пропускает только email из `account_invites`, приглашение пишет `admin-create-user`.
- Пароль, заданный админом, ставит `must_change_password = true`. `App` показывает `ChangePasswordScreen`, пока пользователь не сменит пароль; флаг снимает триггер `password_changed`.
- Интерфейс только прячет вкладки. Настоящая защита в RLS (раздел 4.4).

## 4. База данных (schema public)

### 4.1 Таблицы

**Справочники** (мягкое удаление через `is_deleted`):
- `subjects(id, name, is_deleted, created_by, created_at, updated_at)`
- `chapters(id, subject_id, name, order_index, is_deleted, …)`
- `topics(id, chapter_id, name, order_index, is_deleted, …)` — предмета у темы нет, только через главу.
- `sources(id, name, is_deleted)` — источник вопроса (сборник).

**Вопросы**:
- `questions`:
  - привязка: `id`, `subject_id`, `chapter_id`, `topic_id`, `source_id`, `batch_id` (партия импорта);
  - содержание: `type` (test|matching|open), `content`, `content_ru`, `content_tg`, `image_url`, `correct_numeric_answer`;
  - `version` — оптимистическая блокировка;
  - удаление: `is_deleted`, `deleted_at`, `deleted_by`;
  - автор и даты: `created_by`, `updated_by`, `created_at`, `updated_at`;
  - порядок: `seq` (порядок вставки), `num` (номер в теме, ставит триггер `questions_assign_num`);
  - `linked_ids uuid[]` — тесты, из которых сделан этот вопрос;
  - `nct_difficulty smallint` — сложность для НЦТ (1 лёгкий, 2 средний, 3 сложный; необязательная, любой предмет (размечена вся химия, остальные предметы — по мере поступления данных; массовая запись — `scratch/diff/set.mjs`, в git не идёт); миграция `question_nct_difficulty.sql`, названия — `src/lib/nctDifficulty.ts`). Ставит и фильтрует только главный админ (поле в `QuestionForm`, фильтр и бейдж в `QuestionList`); в подборе билета НЦТ пока не используется.
  - `nct_type text` — метка типа задания НЦТ (необязательная; коды и названия — `src/lib/nctTypes.ts` (полный справочник: тесты, скрипты; химия — `nctTypesChem.ts`); интерфейс берёт список только открытого предмета отдельным файлом — `nctTypesLazy.ts` (`loadNctTypes`, `nctTypeLabel`, `nctSubjectKey`) и хук `hooks/useNctTypes.ts`, 142 типа из анализа НЦТ 2022–2026; миграция `question_nct_type.sql`). Ставит и фильтрует только главный админ (поле в `QuestionForm`, фильтр и бейдж в `QuestionList`); режим НЦТ по меткам подбирает типы заданий. Первичную разметку (≈40 % вопросов химии) сделали правила по тексту (`scratch/nct/classify.mjs`, в git не идёт); все метки сбрасываются запросом `update questions set nct_type = null`.
  - `passage_id uuid → passages`, `passage_order smallint` — вопрос к тексту (английский): обычный `test` с четырьмя вариантами, ссылкой на текст и местом в нём (1–8). У вопроса-пропуска условие пустое. Такие вопросы в билет **поодиночке не берутся никогда** — только текстом целиком (раздел 9, `passageBlocks`).
- `passages(id, subject_id, chapter_id, topic_id, source_id, batch_id, kind reading|cloze, title, content, is_deleted, created_by, created_at, updated_at)` — тексты для чтения и с пропусками (`supabase/sql/passages.sql`); в `cloze` место пропуска — метка `{{1}}`…`{{8}}` (номер = `passage_order`). Права как у вопросов своего предмета (`can_view_subject` / `can_manage_subject`). Откат партии и удаление темы скрывают и тексты.
- `question_options(id, question_id, text, text_ru, text_tg, image_url, is_correct, order_index)`
- `matching_items(id, question_id, side left|right, text, text_ru, text_tg, image_url, order_index, correct_match_id)` — ответ хранится у левого элемента.

**Билеты**:
- `ticket_batches(id, title, subject_id, created_by, generation_params jsonb, created_at)`. Удалить набор может только главный админ (`owner_only_delete_batches.sql`). Поля `generation_params`:
  - выбор: `chapter_ids`, `topic_ids`;
  - состав: `test_count`, `matching_count`, `open_count`, `ticket_count`, `requested{test,matching,open}`;
  - перемешивание: `shuffle_options`, `shuffle_matching`;
  - откуда: `source` (site|telegram|telegram-app|cluster), `lang`;
  - `auto_title`, у кластера — свои поля.
- `tickets(id, batch_id, ticket_number)`.
- `ticket_questions(id, ticket_id, question_id, order_index, question_snapshot jsonb)`. Снимок самодостаточен: `id`, `type`, `content*`, `image_url`, `correct_numeric_answer`, `chapter_name`, `topic_name`, `options[]` (с `is_correct`), `matching_items[]` (с `correct_match_id`); у кластера ещё `cluster_slot`. После замены вопроса `question_id` может быть `null`, а снимок — `{empty: true, type, …}` («пустое место», когда вопросов не хватило).

**Билеты классу** (`supabase/sql/exam_links.sql`):
- `exam_links(code, batch_id → ticket_batches, created_by → auth.users, created_at, closes_at, closed_at, session_start_at, duration_min, review_sent_at)` — запуск набора: `code` — 6 знаков из алфавита без похожих символов (`ABCDEFGHJKMNPQRSTUVWXYZ23456789`), `closes_at` = создание + 24 часа, `session_start_at` — момент общего старта (пусто = зал ожидания; ставит `exam_session_start` = сейчас + 3 с), `duration_min` 5..45 (по умолчанию 30; преподаватель выбирает при старте; конец сессии = `session_start_at + duration_min`, но не позже `closed_at`), `review_sent_at` — когда преподаватель отправил разбор ученикам (до этого разбор ученику не отдаётся).
- `exam_attempts(id, code → exam_links, tg_user_id, tg_username, tg_name, student_name, ticket_id → tickets, started_at, deadline_at (пусто и не используется: срок общий, считается от запуска), finished_at, answers jsonb, score, max_score, lang)`, `lang` (`'ru'`/`'tg'`, по умолчанию `'ru'`, check) — язык билета, его выбирает ученик на экране ввода имени, дальше он зафиксирован для попытки; `unique (code, tg_user_id)` — одна попытка на аккаунт Telegram; вариант до старта меняет преподаватель (`exam_attempt_set_variant`); `answers` — `{id строки ticket_questions: ответ}`; `score` и `max_score` ставит сервер при сдаче; `away_count`, `away_ms`, `away_since` — уходы со страницы билета во время сессии: сколько раз, сколько всего миллисекунд (законченные уходы) и с какого момента ученик не на странице сейчас (пусто — на странице); пишет только `exam_attempt_focus`, сдача закрывает незавершённый уход; `away_closed_at` — когда попытку закрыло правило о выходах (пусто — не закрывало), `away_base_count` / `away_base_ms` — счётчики на момент возвращения ученика преподавателем (правило считает только то, что сверх них), `copy_count` — попытки скопировать текст билета (пишет `exam_attempt_copy`). У запуска `exam_links.away_strict` (по умолчанию `false`) — правило о выходах включено; ставит `exam_session_start` по галочке преподавателя. `exam_links.no_back` (по умолчанию `false`) — режим «без возврата к вопросам», `exam_attempts.pos` — номер (с нуля, по порядку в билете) самого дальнего вопроса, до которого дошёл ученик (пишет только `exam_attempt_advance`, назад не уменьшается).
- Язык: `tg-exam start` принимает `lang` (нет или не `ru`/`tg` — русский) и пишет его в попытку; `open`/`start` отдают язык попытки, на нём снимки, разбор на странице и сообщения бота с разбором (`reviewLines`, `reviewHead`, `reviewButtonText` в `_shared/exam.ts`). Интерфейс страницы ученика (зал ожидания, билет, окно сдачи, результат, разбор, предупреждения об уходе и сохранении, ошибки) — на языке попытки: тексты в `src/exam/i18n.ts`; экран ввода имени переключается сразу при выборе языка. Сервер отвечает ошибками по-русски, для таджикского текст берётся по коду ошибки (`examErrorText`; новый код ошибки в `tg-exam` — добавить перевод, тест `examI18n.test.ts` сверяет список). Русскими остаются сообщение бота перед началом и экраны до выбора языка (загрузка, «Откройте ссылку в Telegram», «Билет не найден»). `generation_params.lang` сайт не пишет.
- Порядок вариантов: у каждого ученика свой — `shuffleOptions(снимок, id попытки)` в `_shared/exam.ts` (тест — варианты; соответствие — левые и правые пункты независимо; `order_index` переписывается 0..n-1, `id` и ключи прежние, поэтому баллы не меняются). Применяется в `tg-exam` к `publicSnapshot` (фаза `running`), к `reviewSnapshot` (`review`) и в тексте разбора в чат (`reviewLines(…, seed)`: буквы A–D и цифры 1–5 как на экране). `open` и вопросы с вариантами вроде «все перечисленные», «оба», «ҳама», «ҳеҷ яке» не перемешиваются. В базе порядок не хранится — он вычисляется заново от id попытки.
- Чтение: автор запуска (`created_by = auth.uid()`) и главный админ; ученики таблицы не читают никогда (их обслуживает только `tg-exam` сервисным ключом); у `anon` прав нет. Запись — только RPC и сервисный ключ (раздел 4.2).

### 4.4 RLS (кратко; точный текст — `select * from pg_policies`)

- RLS включён на всех таблицах. Во всех политиках `(select auth.uid())`: вычисляется один раз на запрос (`rls_initplan_indexes.sql`). То же с функциями прав в политиках чтения: пишите `(select public.is_owner())`, `(select public.my_rank())`, а не голый вызов — иначе функция выполняется на каждую строку (`perf_round1.sql`).
- **questions**:
  - SELECT: admin — всё; user — неудалённые; subject_teacher — неудалённые своих предметов; subject_admin — все своих предметов.
  - DELETE — только админ (`security_round5.sql`; сайт физически не удаляет, только `is_deleted`).
  - INSERT и UPDATE — по `can_manage_*`.
- **question_options, matching_items**: SELECT — админ всё (`(select auth_role())`, один раз на запрос), остальные — если виден сам вопрос (`exists` по `questions`, там действует политика «Просмотр вопросов»): user — неудалённые, subject_teacher — неудалённые своих предметов, subject_admin — все своих предметов (`perf_round1.sql`; до него видимость проверяла функция `can_view_question` на каждую строку — до 80 % времени загрузки банка). INSERT, UPDATE, DELETE — по-прежнему `can_manage_question`.
- **chapters, topics, subjects**: SELECT для вошедших, DELETE только админ, INSERT и UPDATE для управляющих предметом.
- **ticket_batches, tickets, ticket_questions**: свои наборы; owner видит все. Кластерные (`is_cluster_batch`) видит и создаёт только owner. DELETE наборов — только owner.
- **exam_links, exam_attempts**: только SELECT, и только своих запусков (`created_by`) или главному админу; попытки — через `exists` по `exam_links`. INSERT, UPDATE и DELETE у ролей API отозваны — пишут RPC и сервисный ключ. У учеников (без входа на сайт) доступа нет вовсе.
- **question_usage**: SELECT для вошедших; пишет только триггер.
- **duplicate_dismissals**: просмотр, добавление и удаление — `can_manage_question` (админ и главный админ, админ по предметам — только своих предметов). **client_errors**: только owner (пишется через RPC `report_client_error`).
- **Анонимы**: `security_round4.sql` отозвал все права на таблицы, кроме SELECT на `game_sessions`; игра ходит через `game_*` (security definer).
- **profiles**:
  - SELECT — себя или админ.
  - UPDATE — себя; owner — всех; админ — не-админов.
- **user_subjects**: SELECT — своё или админ; INSERT и DELETE — только owner.
- **site_releases, site_release_items**: SELECT по `my_rank()` и предмету; запись — owner.
- **site_tips**: SELECT по `my_rank()` и предмету; прямой записи нет ни у кого (права INSERT/UPDATE/DELETE отозваны) — только `add_site_tip`. **site_tip_seen**: SELECT и INSERT — только свои строки.
- **audit_logs**: SELECT — админ.
- **generation_usage**: SELECT — своё или админ.
- **generation_settings**: SELECT — все, UPDATE — админ.
- **game_\***: ведущий через `host_id`. Команды ходят только через RPC с секретом.

### 6.2 `App.tsx`

- Состояния до вкладок:
  - пока идёт `isLoading` — спиннер;
  - без пользователя — `AuthModal`;
  - при `profile.must_change_password` — `ChangePasswordScreen`.
- `TabType` = questions | taxonomy | generator | saved_tickets | bulk_import | users | stats | usage | quality | trash | cluster | releases | games | exams.
- Ограничения вкладок: admin — users, stats, trash; staff — taxonomy, bulk_import, quality («Качество банка», админ по предметам видит только свои предметы); owner — cluster, usage («Подборы»). «Билеты классу» (`exams`, `#exams`) видна всем ролям; `#exams/<id набора>` сразу открывает окно запуска этого набора (кнопка «Запустить классу» в «Архиве билетов» и в «Генераторе»). При недоступной вкладке открывается generator.
- Раздел записывается в адрес (`TAB_HASH`: `#generator`, `#archive`, `#import`, `#news` …). Форма вопроса (`#questions/…`) и меню «Ещё» на телефоне — отдельные шаги истории, «Назад» закрывает их по очереди.
- Навигация: `SideNav` (группы разделов), на телефоне нижняя полоса и меню «Ещё». Тема: `useTheme` (`light` | `dark` | `system`, `localStorage.examiner_theme`), кнопка `ThemeToggle`; `theme-init.js` ставит класс `dark` до загрузки React.
- `UpdateBanner` периодически и при возврате на вкладку сверяет `/version.json` с `__BUILD_ID__`: новая версия замечена первой проверкой после открытия — страница перезагружается сама, позже — кнопка «обновить» (`src/lib/autoUpdate.ts`).
- Системное `confirm()` не используется: `confirmAction()` (`lib/confirm.ts`) показывает `ConfirmDialog`.
- Вкладки грузятся через `React.lazy`. Последняя вкладка хранится в `localStorage.examiner_active_tab`.
- Форма вопроса (`QuestionForm`) открывается поверх вкладки. Перед закрытием `App` спрашивает о несохранённых изменениях.
- «Своя игра» открывается в новом окне `/game`.

Хуки:
- `useAuth()` возвращает `{user, profile, session, isLoading, isAdmin, isOwner, isStaff, subjectIds, canManage, signIn, signUp, signOut, refreshProfile}`. - `useTips(enabled)` возвращает `{tips, markSeen}` — подсказки из `next_site_tips` (нет функции в базе или ошибка — пустой список, без сообщения) и отметка «показано» (upsert в `site_tip_seen` с `ignoreDuplicates`).

Сложность (`questions.nct_difficulty`, 1/2/3): `pickNct(..., difficulty)` получает доли лёгких/средних/сложных в % для тестов и соответствий (`NctDifficultyShares`, по умолчанию 50/40/10, поля в «Составе билета» при режиме НЦТ, LS `examiner_nct_diff`, сумма 100; переключатель «вкл/выкл» — LS `examiner_nct_diff_on`, выключен → `difficulty = null`: сложность не учитывается ни у тестов, ни у открытых, в параметрах `nct_difficulty: null`), открытые всегда `NCT_OPEN_DIFFICULTY` = 2/3/2 из 7; `difficultyTargets` раскладывает места методом наибольших остатков и перемешивает, `pickOne` берёт вопросы нужной сложности, при нехватке — ближайшей, затем без оценки (в заметках «взята ближайшая»); в параметрах набора `nct_difficulty`. Замена вопроса в готовом билете (`nctCandidatesFor`, `planNctTopicRemoval`) сначала берёт вопросы той же сложности (`NctSlotInfo.difficulty`, у места — `Slot.nctDifficulty`), нет таких — любой. ## 10. Потоки

**Создание билетов на сайте** (`TicketGenerator.handleGenerate`):
1. Проверка `checkSettings` по лимитам: обычный пользователь — `useUserLimits`, админ — `LIMITS` с 50 вариантами.
2. Параллельно: `loadLightPool` и `question_counts` (из кэша, если он моложе 60 с).
3. `fitSettings` по реальному пулу: если вопросов мало, показывается уведомление.
4. `chapterTotalsFromCounts`, затем `pickTickets`. Позиция j во всех билетах берётся из одной темы, соседними вопросами сборника; среди подходящих вариантов предпочитается тот, где вопросы реже попадали в билеты (`question_usage`). Главы делят позиции по охвату, вопросы не повторяются, пока хватает. Связанные вопросы разводятся по разным билетам.
5. `hydrateTickets` → `snapshotTickets` (перемешивание вариантов и правой колонки).
6. Название: своё или `autoBatchTitle`.
7. `rpc('save_ticket_batch')`. Триггер проверяет лимиты; при ошибке откатывается всё.
8. `withSelectionInfo` + `describeSelection` по уже загруженной структуре; набор сохраняется в `localStorage.examiner_tg_generated_batch`.
9. Сброс кэша `saved_ticket_batches`, `recent_batches`, `generation_usage_today`.

**Бот и Mini App:** тот же подбор в `_shared/generate.ts`. Добавляются `acquire_generation_lock` (180 с), проверка назначенных предметов, дневной лимит по `generation_usage`. Файл присылает бот.

**Скачивание:** `exportLazy.buildTicketsFile` (docx; для `both` — ZIP с папками «Русский» и «Тоҷикӣ»). Если у предмета есть шаблон, в ZIP добавляются ключи (`keyArchiveExtras`). Шаблоны: chem, phys, bio, taj (по названию предмета), taj-cluster.

**Правка готового набора** (`BatchEditor`, owner):
1. `fetchBatchSlots` читает билеты набора, `fetchTopicPool` — вопросы выбранных тем.
2. `candidatesFor` или `planTopicRemoval` строят замены, `buildRowChanges` — изменения строк.
3. `saveBatchChanges` вызывает `rpc("update_batch_questions")` одной транзакцией, `generation_params` обновляется (`paramsAfterEdit`).
4. Если вопросов не хватило, остаётся «пустое место», в Word оно выделено красным. Скачивание как обычно.

**Качество банка** (staff): `loadBankQuestions` → `bankIssues` и `findPairs`; можно проверить весь предмет или одну главу (`chapterId`; дубли тогда ищутся только внутри главы). Результат кэшируется (`scanCache`, ключ `examiner_quality_scan_<предмет>` или `_<предмет>:<глава>`), при заходе сверяется по числу вопросов и времени последнего изменения (для главы — только её вопросов). «Не дубль» пишет `duplicate_dismissals`.

**Правка вопроса** (`QuestionForm`):
1. Вставить новые варианты.
2. Обновить вопрос с условием `.eq('version', старая)`. Если строк 0, значит кто-то правил параллельно, будет ошибка.
3. Удалить старые варианты.

Новый вопрос вставляется с `version: 1`.

**Удаление:**
- Вопрос: `withUndo`. Строка сразу скрывается в интерфейсе, `update is_deleted = true` уходит через 5 с, если не нажали «Отменить». Триггер пишет `deleted_by`.
- Наборы удаляются так же, но физически.
- Глава или тема в `TaxonomyManager` мягко удаляет и свои вопросы.

**Импорт** (`BulkImport`):
1. Разбор файла в браузере.
2. Предпросмотр и назначение предмета, главы и темы.
3. Создаётся `import_batches`.
4. Каждая строка сохраняется отдельно, дубли в теме пропускаются.
5. Картинки загружаются в Storage только на этапе сохранения.

**Привязка Telegram:** `create_telegram_link_code()` → ссылка `t.me/<бот>?start=КОД` → бот записывает `telegram_links(chat_id, user_id)`.

**Новый пользователь:** `admin-create-user` → приглашение → `auth.users` → `handle_new_user` создаёт профиль → первый вход → `ChangePasswordScreen`.

**«Что нового»:**
1. Файл `releases/*.sql` → `add_site_release`.
2. `useReleases` читает версии, видимые по рангу.
3. Непрочитанные показывает `WhatsNewModal`.
4. Закрытие окна пишет `site_release_reads`.
5. pg_cron раз в минуту вызывает `release-notify`, если есть версии без `notified_at`: рассылка в Telegram по роли пользователя. Кнопка «Что нового» в боте показывает только пункты `scope = site`.

**Подсказки «А вы знали?»:**
1. Файл `releases/*.sql` (или `site_tips.sql`) → `add_site_tip(версия, текст, якорь, раздел, min_rank)`.
2. `TipPopup` (в `App` рядом с `WhatsNewModal`) берёт список `next_site_tips` и при смене раздела и раз в 2 с проверяет условия `shouldShowTip`: не раньше 8 с после входа, одна за заход (флаг в памяти и `sessionStorage`), одна в сутки (`localStorage` `examiner_tip_last:<userId>`), не при открытом или уже показанном в этот заход «Что нового», не поверх окон (`[aria-modal=true]`, форма вопроса, меню «Ещё»), не в разделе «Что нового» и не у `game_teacher`.
3. Показывается самая новая подсказка, чей якорь сейчас виден (`[data-tip=ключ]` с размером, не скрыт стилями; берётся первый видимый — пункт меню есть в нескольких меню; для `nav-*` запасной якорь — кнопка «Ещё» `nav-more` на телефоне). Якоря нет — подсказка ждёт и не отмечается. Якорь за краем экрана прокручивается в центр.

Клик по затемнению, Esc, «Понятно» и крестик закрывают; якорь пропал (смена раздела) — подсказка закрывается без повтора. Ключи якорей: `nav-<раздел>` (`tipKeyOfTab`: `nav-saved-tickets`, `nav-exams`, `nav-cluster`…; боковое меню, полоса разделов, меню «Ещё», нижнее меню), `nav-more`, `archive-variants` («Посмотреть варианты» в карточке набора), `telegram-link` (кнопка бота в шапке), `cluster-zip-drop` (все ZIP сразу), `cluster-history` («История» кластеров). Для функций внутри окон якорь — видимый без окна элемент, текст «откройте … — …».

**Открытие из памяти браузера** (`public/sw.js`, регистрирует `registerServiceWorker` из `main.tsx` — только обычный сайт и только в выложенной сборке): страница сайта — сначала сеть, нет ответа за 1,5 с — сохранённая копия (кэш `examiner-shell-v1`), свежая докачивается в фоне; `/assets/*` — из кэша `examiner-assets-v1` (последние 250 файлов), иначе из сети; запросы к базе, `/tg`, `/version.json` и адреса с расширением сценарий не трогает. Данные банка без сети не открываются — только сам сайт и справочники из `queryPersist`. Меняете правила кэша — поднимите номер в имени кэша. Тест `tests/autoUpdate.test.ts`.

**Билеты классу** (раздел «Билеты классу» на сайте, страница `/tg/exam`):
1. **Запуск.** Преподаватель в `ExamsView` выбирает свой обычный набор (автор набора или главный админ; кластерные нельзя) и нажимает «Запустить классу» → RPC `exam_link_create` создаёт `exam_links` с кодом на 24 часа. Окно показывает ссылку `t.me/<бот>?start=exam_КОД`, QR и кнопку «Отправить мне в Telegram» (`tg-exam: link_send`).
2. **Бот.** Ученик открывает ссылку → `telegram-bot` (`onExamStart`) отвечает кнопкой «Войти в билет» → страница `/tg/exam?c=КОД` внутри Telegram.
3. **Ученик.** `ExamApp` вызывает `tg-exam: open`; на экране имени ученик выбирает язык («Русский» / «Тоҷикӣ», по умолчанию русский); после ввода имени — `start` (с `lang`): сервер выбирает случайный вариант набора и входит в зал ожидания: сервер выбирает случайный вариант и создаёт попытку без срока (одна попытка на аккаунт Telegram). Страница `ExamLobby` показывает крупный номер варианта и опрашивает `open` раз в 3 с (`EXAM_POLL_MS`); когда преподаватель нажал «Начать», все видят отсчёт 3-2-1 (по часам сервера) и открывается билет с общим концом сессии. Вопросы идут по одному, каждый ответ уходит в `save` сразу и атомарно дописывается в `exam_attempts.answers`; таймер считает по часам сервера (`now` в ответах). `submit` (или автосдача по истечении срока — просроченные попытки закрывает любое обращение к `tg-exam`) → ученик сразу видит свой балл (без верных ответов).
4. **Зал ожидания и старт (преподаватель).** Пока `session_start_at` пусто, `SessionLobby` показывает пришедших, у каждого — выбор варианта (RPC `exam_attempt_set_variant`, только до старта) и длительность 5–45 мин; «Начать» → RPC `exam_session_start(код, минуты, правило о выходах, без возврата)` (идемпотентна, нужен хотя бы один ученик; старт = сейчас + 6 с (`EXAM_START_LEAD_SEC`), цифры 3-2-1 клиент показывает за последние 3 с; отказывает, если ссылка закроется раньше конца сессии; повторное нажатие ничего не меняет).
5. **Таблица.** `ExamBoard` опрашивает `exam_attempts` (RLS — только свои запуски) раз в 3 с, пока запуск открыт: имя, вариант, «Уходил», баллы, статус (идёт, сдал, время вышло). `QuestionStats` — доля верных по каждому заданию, `ExamExcelButton` — Excel.
   - **Уход со страницы.** Пока идёт билет, `ExamTicket` слушает `visibilitychange`, `pagehide`/`pageshow`, `blur`/`focus` окна и события Telegram `deactivated`/`activated` (`applyFocusSignal`: считаются события, а не состояние; нажатие на страницу снимает все причины) и через `createAwayReporter` шлёт `tg-exam: focus` — уход сразу (`fetch` с `keepalive`), возвращение с длительностью; сообщения идут по одному и по порядку, сбой связи повторяется, недошедший уход заменяется возвращением. При открытии страницы уходит одно «вернулся» без длительности (`arrive`) — оно закрывает уход того, кто закрыл страницу и открыл её снова. `ExamBoard` показывает столбец «Уходил» (`awayView`: «сейчас не на странице · 0:14» или «2 раза · всего 48 с») и всплывающее предупреждение, когда у кого-то вырос `away_count` (`newAwayNames`; первый опрос только запоминает). В Excel — столбцы «Уходил, раз» и «Вне страницы, с». Ученик после возвращения видит строку «Вы уходили со страницы билета… Преподаватель это видит». Без правила о выходах (ниже) штрафов и автосдачи нет: бывают ложные срабатывания (звонок, шторка уведомлений). Окно поверх экрана, по которому не нажимают, и второе устройство страница не видит.
   - **Правило о выходах (открытое).** В зале ожидания (`SessionLobby`) галочка «Закрывать билет за выходы» (включена по умолчанию) → `exam_session_start(код, минуты, p_away_strict)` пишет `exam_links.away_strict`. Пороги — `AWAY_LIMIT_COUNT` = 3 и `AWAY_LIMIT_MS` = 10 000 в `_shared/exam.ts` (единственное место; в базу передаются параметрами). После каждого `focus` и при `open` идущей попытки `tg-exam` вызывает `exam_attempt_away_check` (`enforceAway`): при `away_strict` и 3 выходах **или** больше 10 с вне страницы (считая незаконченный выход) база одним обновлением закрывает попытку (`finished_at`, `away_closed_at`), функция ставит балл. Ученик видит правило заранее (зал ожидания — `lobbyRules`, перед стартом и в билете — `awayRule` со счётчиком `awayUsed` по данным сервера), после закрытия — экран «Билет закрыт: вы выходили со страницы» с баллом; пока сессия идёт (`canReturn`), страница раз в 3 с спрашивает `open` (`ReturnWatcher`). Преподаватель в `ExamBoard` видит «билет закрыт за выходы» и кнопку «Вернуть в билет» → RPC `exam_attempt_reopen` (автор запуска или главный админ, только пока сессия идёт): `finished_at`, балл и `away_closed_at` стираются, ответы остаются, `away_base_*` = текущие счётчики. Без галочки всё как раньше: выходы только записываются. Ученик, который ушёл и не вернулся, закрывается при возвращении (или обычным концом сессии).
   - **Запрет копирования.** Мини-приложение — обычная веб-страница: запретить снимок и запись экрана она не может (в Telegram Mini Apps такой настройки нет, в отличие от каналов). Что сделано: на экране билета текст не выделяется (`.exam-nocopy` в `exam.css`; клетки ответа — как обычно), события `copy`, `cut`, `contextmenu` и `dragstart` отменяются (`src/exam/copyGuard.ts`: события одного нажатия за 1,5 с — одна попытка), каждая попытка уходит в `tg-exam: copy` → `exam_attempt_copy` (`copy_count`, только пока попытка идёт), ученик видит «Попытка записана». В `ExamBoard` — столбец «Копировал» и всплывающее предупреждение (`newCopyNames`), в Excel — «Копировал, раз» и «Закрыт за выходы». Билет за копирование не закрывается.
   - **Без возврата к вопросам.** Галочка в зале ожидания (выключена по умолчанию) → `exam_links.no_back`. В билете нет «Назад», полоса номеров не нажимается; «Далее» сначала дожидается сохранения ответа, о вопросе без ответа предупреждает один раз, затем шлёт `tg-exam: advance` (номер следующего вопроса) → `exam_attempt_advance`. Сервер при `no_back` не принимает `save` для вопросов раньше `pos` (`question_locked`), а после перезахода страница открывается с вопроса `pos` (`noBackStartPos`). Не дошедший `advance` только ослабляет запрет (ученик после перезахода вернётся на вопрос раньше), ответы не теряются.
   - **Полный экран.** При открытии билета `ExamTicket` вызывает `requestFullscreen` (Telegram 8.0+), `enableClosingConfirmation` (6.2+) и `disableVerticalSwipes` (7.7+), при выходе из билета — обратные; версии проверяются `isVersionAtLeast`, на компьютере и в старых приложениях полный экран просто не включается. 2,5 с после запроса и после события `fullscreenChanged` сигналы потери фокуса уходом не считаются (`quietUntil`). Шапка билета учитывает `--tg-safe-area-inset-top` и `--tg-content-safe-area-inset-top`.
   - **Водяные знаки** (`src/exam/watermark.ts`). Поверх билета — бледная повторяющаяся подпись «имя ученика · код запуска» (`.exam-wm`, нажатия проходят сквозь неё; имя приходит в `open` как `studentName`): снимок экрана показывает, чей он. В каждом вопросе между условием и ответами — мелкая цитата `AI_NOTICE` цветом обычного текста (по-русски и по-английски) о том, что решить экзамен за другого — значит украсть у него знания, и пометка «Это задание идущего экзамена»; её видят все, кому покажут задание (друг, репетитор, ИИ-помощник). Цитата читаемая намеренно: на снимке ИИ видит только пиксели, невидимый человеку текст и азбуку Морзе он не разберёт. В разборе после сдачи строки нет.
   - **Приглашение прошлых учеников.** `InviteStudents` (в окне запуска после создания ссылки и в зале ожидания): преподаватель выбирает свой прошлый запуск и учеников (по умолчанию все) → `tg-exam: invite_send {code, from, ids}`. Функция проверяет, что оба запуска одного автора, берёт попытки прошлого запуска (`inviteTargets`: одно сообщение на аккаунт Telegram, не больше `INVITE_MAX` = 100) и шлёт каждому личное сообщение бота с кнопкой «Войти в билет» на языке его прошлой попытки (`inviteText`). Ответ — `{sent, failed}`; не дойдёт тому, кто остановил бота. Попытка по-прежнему одна на аккаунт Telegram (`unique (code, tg_user_id)`).
   - **Экран классу.** Кнопка «На экран» в `ExamBoard` (пока запуск открыт) открывает в новой вкладке `/exam/screen/КОД` — страницу для проектора: в ожидании крупный QR-код и имена вошедших, затем «Скоро начнём…» и цифры 3-2-1, во время билета крупный таймер, «Сдали N из M» и список «Не на странице билета» с именами и временем (так решил пользователь: имена видит весь класс), маленький QR-код для опоздавших, в конце «Время вышло» или «Билет закрыт» и «Работы приняты». Баллы на экран не выводятся. `ExamScreen` раз в 3 с читает запуск (`fetchExamLink`) и попытки (`fetchAttempts`) под RLS преподавателя, после конца опрос останавливается; время — по часам сервера (`fetchServerNow` → RPC `game_time`, сверка раз в минуту), поэтому отсчёт и таймер совпадают с телефонами учеников. Сам показ — `ExamScreenView` (только свойства, без запросов). Экран ничем не управляет: начинает и закрывает запуск преподаватель в таблице.
6. **Закрытие.** «Закрыть» → `exam_link_close`; ссылка перестаёт принимать новых и ответы идущих, незавершённые попытки закрываются с сохранёнными ответами и получают баллы при ближайшем обращении к `tg-exam` (`finishExpired`); преподавателю в бот приходит итог (`notify_closed`).
7. **Разбор.** (повторная рассылка меньше чем через 10 секунд после прежней — ответ 409 «Разбор только что отправлен», `reviewJustSent`; двойной щелчок в `ExamBoard` гасит защита от повторного входа; новый запуск набора, которому уже разослали разбор, требует отдельного подтверждения — `needsRelaunchConfirm`) «Отправить разбор ученикам» (только после закрытия) → `review_send`: ставится `review_sent_at`, каждому сдавшему приходит текст с ошибками и кнопка «Открыть с формулами и рисунками» (`/tg/exam?c=КОД&review=1`, действие `review`). До отправки разбора ученик ключей не получает.
8. **Порядок выкладки.** SQL `exam_links.sql`, затем `security_round5.sql` (не `update_batch_questions.sql` после него) → `tg-exam` (`--no-verify-jwt`) → `telegram-bot`, `tg-app` → сайт.

**Своя игра:**
1. Ведущий (`GameHost`, только owner) вызывает `game_create`.
2. Пакет вопросов берётся из `game_packs`.
3. Ведущий пишет `game_sessions.board` (табло, таймер, счёт).
4. Все экраны подписаны на Realtime: канал `game-<код>-<случайный суффикс>`, `postgres_changes` по `game_sessions` с фильтром `code=eq.<код>` (`useGameSession` в `src/game/api.ts`).
5. Команды (`GamePlay`) входят через `game_join`, `game_rejoin` (ПИН) и отвечают через `game_buzz`, `game_team_act` с секретом из `game_secrets`.
6. Время синхронизируется через `game_time` (`useServerClock`).
7. Итоги и разбор попадают в `game_results`; выгрузка в Excel — `review.ts`.

## 13. Разработка, проверки, выпуск

- Запуск: `npm install`, `npm run dev` (порт 5173; конфиг `.claude/launch.json`, имя `dev`).
- Проверки:
  - `npx tsc -b` и `npx vitest run` — перед каждым коммитом;
  - `npm run build` — тесты, типы и сборка вместе; то же и `npm audit --omit=dev --audit-level=high` запускает GitHub Actions (`ci.yml`) на каждый пуш;
  - `npm run test:db` — тесты прав доступа на встроенном Postgres (раздел 14); запускайте после правок в `supabase/sql`. Входит в CI (`ci.yml`, после сборки).
  - после новых цветовых классов Tailwind — `npm run theme:dark` и коммит `src/dark.css`.
- `.env` в git не хранится, переменные — в `.env.example`:
  - сайт: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_TELEGRAM_BOT_USERNAME`, `VITE_SUPPORT_TELEGRAM` (необязательно);
  - скрипты импорта: `IMPORT_ADMIN_*`.
- **Импорт сборников** (рус+тадж, ключи, дубли, связи, вставка, сверка) — порядок в `CLAUDE.md`, раздел «Импорт сборников». В базе новая глава = глава + темы «RU / TG» + источник + партия в `import_batches`.
- **Версия и «Что нового»** (правила — в `CLAUDE.md`):
  1. `git fetch`.
  2. Взять следующий номер после последнего файла в `supabase/sql/releases/` на `origin/main`.
  3. Поднять версию в `package.json` и в двух первых `"version"` в `package-lock.json`.
  4. Создать `supabase/sql/releases/ГГГГ-ММ-ДД_<версия>.sql`.
  5. Пункты с `min_rank` и `kind` писать одной понятной фразой.
  6. К новой функции сайта для преподавателей — `select public.add_site_tip(…)` с якорем `data-tip` (раздел «Подсказки» выше); если якоря нет, поставьте атрибут на элемент.
- **SQL:** `npx supabase db query --linked -f supabase/sql/<файл>.sql` (проект привязан), либо SQL Editor. Политики и функции пишите идемпотентно (`create or replace`, `drop policy if exists`).
- **Edge Functions:** `npx supabase functions deploy <имя> --project-ref ovxrgkyexuudgtqglegk` (`telegram-bot`, `tg-app` и `tg-exam` с `--no-verify-jwt`).
  - **Любая правка `_shared/*` требует передеплоя `telegram-bot`, `tg-app` и `tg-exam`.** `send-to-telegram` и `admin-*` от `_shared` не зависят.
  - **«Билеты классу»: сначала `supabase/sql/exam_links.sql`, потом `supabase functions deploy tg-exam --no-verify-jwt`** (функция читает и пишет эти таблицы), затем `telegram-bot` и `tg-app` (первый разбирает `exam_КОД`, второй использует общий `tgInitData.ts`), затем сайт. Секрет `TELEGRAM_BOT_TOKEN` у `tg-exam` тот же, что у `telegram-bot`.
  - `release-notify` деплоится с `--no-verify-jwt` и использует `_shared/releases.ts`.
  - Перед деплоем сделайте `git pull`: деплой из устаревшей копии затирает чужие правки в продакшене.
- **Сайт:** `git push` в `main` → Vercel.
- Деплой в продакшен, применение SQL и пуш делает пользователь или подтверждает явно.
- **CSP** (`vercel.json`) запрещает встроенные скрипты и обработчики вроде `onload=`. Скрипты разрешены только свои и с `telegram.org`, стили и шрифты — с Google Fonts, запросы — только к Supabase проекта. Новый внешний домен нужно добавить в CSP, иначе он не загрузится.

## 15. Ловушки

- Описание версии в боте: команда `/release 1.0.0` (также «релиз 1.0.0», без номера — последняя версия) и кнопка под рассылкой; разбор — `parseReleaseCommand` в `_shared/releases.ts`, ответ — `screenRelease` в `telegram-bot`: все пункты версии, кроме `game`, по роли и предметам пользователя.
- Запрос справочника в `queryFn` обязан бросать ошибку (`if (error) throw error`): иначе сбой сети кэшируется как пустой список на 5 минут.
- Роль без доступа к банку (`game_teacher` и любая новая) в боте и мини-приложении получает пустой список предметов: `allowedSubjectIds` в `_shared/generate.ts` разрешает весь банк только ролям `user` и `admin` — как `can_view_subject` в базе.
- Supabase отдаёт максимум 1000 строк за запрос: большие выборки читайте через `fetchAllPages` или `loadLightPool` (окна по id). Не листайте большие выборки смещением (`range`): для страницы N база собирает и все предыдущие строки вместе с вложенными таблицами.
- Под RLS индекс работает только с операторами, помеченными leakproof (сравнение uuid, чисел, дат). Пересечение массивов (`&&`), `ilike` и подобные Postgres обязан проверять после прав каждой строки, то есть полным перебором таблицы — даже если индекс есть. Нужен поиск по такому индексу — делайте функцию `security definer`, которая ищет по индексу и сама проверяет видимость найденных строк (образец — `questions_linking_to`).
- Замеры на живой базе делайте по одному запросу и немного: 22.11.2026 серия тяжёлых `explain analyze` замедлила сервер примерно в сто раз на десятки минут (тот же запрос: 12 мс → 1,7 с). Планы и логику проверяйте на встроенном Postgres (`npm run test:db`).
- Сервер базы слабый: одиночный запрос идёт миллисекунды, но несколько тяжёлых одновременно замедляют друг друга в десятки раз (замер 22.11.2026). Не запускайте параллельно больше 6 запросов и не тяните вложенные `question_options` без необходимости.
- `.in('id', [...])` идёт в URL: держите не больше ~100 uuid за запрос.
- Мягкое удаление: почти везде нужен `.eq('is_deleted', false)`. Для вложенных тем — `.eq('topics.is_deleted', false)`.
- Снимок вопроса в билете не меняется при правке банка. Старые снимки без `is_correct` и `correct_match_id` дополняет `enrich`.
- Кластерные партии (`source='cluster'`) скрывает RLS; фильтровать их в коде отдельно не нужно.
- Порядок вопросов в теме: `num`, затем `seq`, `created_at`, `id` (`compareInTopic`). Не сортируйте только по дате.
- Каждый последовательный запрос к базе в Сеуле заметно задерживает отклик. Независимые запросы делайте через `Promise.all`; главы и темы читайте одним вложенным `select`.
- Сборка Word идёт в основном потоке: 4 варианта ≈ 0,3 с, 20 RU+TJ ≈ 2 с, 50 RU+TJ ≈ 4,5 с.
- Внутри `onAuthStateChange` не делайте долгих цепочек запросов: колбэк держит блокировку сессии supabase-js.
- Счётчик `question_usage` ведёт триггер: не обновляйте его из кода.
- Вопрос с `passage_id` нельзя брать в билет отдельно от своего текста: любой новый подбор (кластер, бот, замена) обязан либо брать блок `passageBlocks`, либо отфильтровать такие вопросы (`!q.passage_id`).
- Английский текст в Word набирайте с `plain = true`: слеш в «he/she», «and/or», «24/7» иначе превращается в дробь-формулу.- Бланки ответов строит `scripts/omr-blanks.mjs`: HTML для печати (`scratch/blanks/out`, PDF из Edge/Chrome, масштаб 100 %) и `layouts.generated.ts` одним запуском. Меняя размеры или места кружков, перепечатайте бланки, иначе распознавание сдвинется; код бланка (квадратики внизу справа) нельзя менять без правки раскладки и `BLANKS`.
- Распознавание проверено на нарисованных снимках и на семи реальных фото бланка `chemphys` (бумага изогнута, снимок перевёрнут на 180°, синяя и чёрная ручка, замазка корректором). Главное, что показали реальные снимки: печатные кружки и рамки клеток лежат не там, где в раскладке, на 0,5–1 мм. Поэтому `refineRowOffset` ищет сдвиг ряда в пределах ±0,9 мм (`ROW_SHIFTS`); если кольца ряда при этом совпали плохо (ниже `ROW_SURE`), при чтении отметок `rowOffset` ищет дальше, до ±2,1 мм (`ROW_SHIFTS_FAR`: на фото `taj` столбец 17–20 у приподнятого края уезжает на 1,2–2,1 мм); проверка раскладки дальним поиском не пользуется. `ringScore` сверяет кружки уже со сдвигом ряда, а клетки открытых ответов читаются внутри найденной рамки (`fitOpenFrame`; остатки линий рамки в окне гасятся, но пятно у края окна остаётся, если настоящая линия рамки видна отдельно снаружи, через светлый зазор, — это тонкая «1», написанная вплотную к линии; клетка, где цифра не нашлась, перечитывается с мягким порогом `OPEN_SOFT_K` — так находится бледный карандаш). Пороги: `FILL_ON`, `RING_MIN` (чужая раскладка даёт ring ≤ 0,13, свой бланк — около 1). Метки ищутся среди самых крайних квадратов кадра; если бланк так не нашёлся или нашёлся сомнительно (средняя оценка кружков ниже `RING_AVG_SURE`), включается запасной поиск `findMarkersWide`: четвёрки собираются по форме бланка из всех квадратов кадра. Он нужен для снимков стопки, где в кадре соседние листы: их метки ближе к углам кадра, а четвёрка с меткой нижнего листа проходит и код, и медиану кружков (кружки идут с постоянным шагом) — поэтому из прошедших берётся четвёрка с лучшей средней оценкой кружков (на 19 фото бланка `taj`: у настоящей 0,84–0,98, у смешанной 0,61–0,65). Если и у лучшей четвёрки средняя ниже `RING_AVG_SURE`, бланк принимается, только когда кольца рядов находятся дальним поиском (`ringsFar` ≥ `RINGS_FAR_MIN`: у изогнутого листа ≥ 0,94, у четвёрки с чужой меткой ≤ 0,79). Последняя попытка, если бланк не нашёлся: порог меток `LAST_K` 0,8 (бледная печать), широкие допуски формы четвёрки (сильный наклон), общий сдвиг квадратиков кода до 1,2 мм (`CODE_SHIFTS`, загнутый край); кружки проверяются так же строго. Клетка открытого ответа, уехавшая отдельно от строки, ищет свою рамку (`CELL_OFF`/`CELL_SURE`). Тесты — `tests/omrHard.test.ts`. Лист, сложенный пополам (сгиб и выгнутые половинки: кружки за сгибом уезжают на 2–3 мм, столбцы одного соответствия — по-разному), читается через `seatCircles`: если кружки не сошлись, у четвёрок с верным кодом место каждого блока (столбик тестов, таблица соответствия) ищется со своим сдвигом для каждого столбца; бланк принимается, только если кольца совпали и в среднем (`SEAT_AVG`), и в каждом блоке (`SEAT_WORST`: у настоящих ≥ 0,76, у ложных ≤ 0,67). `toPhoto` при этом остаётся плоским. Групповое фото (несколько бланков в кадре): читается один бланк, остальные только считает `countBlanks` (перебор четвёрок по форме вне прочитанного бланка → код → кружки); `readGray` ставит результату `more` (предупреждение `MORE_TEXT`, строка в стопке), а если не прочитан ни один и бланков хотя бы два — отказывает с `MANY_TEXT`. Живая камера (`probeGray`) бланки не считает. Подсказка «не виден такой-то угол» (`findMissingHint`) называет угол, только если по трём меткам бланк ложится на снимок: остальные тёмные пятна (закрашенные кружки, код) попадают на свои места раскладки; иначе угол не называется — закрашенные кружки того же размера, что метки, и случайная тройка указывала не туда. Нейросеть цифр (`digitNn.ts`) — маленькая свёрточная сеть (14×14 → свёртка 3×3×8 → максимум 2×2 → свёртка 3×3×16 → 64 → 10). Обучается скриптом `scripts/train-digit-nn.py` (python с numpy и scipy; эталоны рисует `scripts/digit-synth.mjs`) на нарисованных эталонах и реальных цифрах с бланков из `scripts/real-digits.json` (обезличенные картинки 14×14 с меткой и пачкой, без фото и имён; каждая повторяется 20 раз со случайным поворотом, наклоном, растяжением, сдвигом и толщиной штриха — без этих искажений новые пачки точность почти не поднимали). Честная проверка — `python scripts/train-digit-nn.py --holdout <пачка>` (пачка не идёт в обучение, веса не пишутся). На 1147 цифрах пятнадцати пачек, каждая пачка отложена по очереди, два начальных числа: 90,3 % верных (прежняя сеть 196 → 48 → 10 со сдвигом и утолщением — 80,2 %). Наборы данных сравнивают по сумме запусков `--seed 1`, `2`, `3`: один запуск гуляет на несколько процентов. Что сеть не исправит: клетка вырезается с отступом 0,9 мм и переводится в чёрно-белую, поэтому крупная цифра обрезается, тонкая рвётся, жирная сливается (`openBox` в `recognize.ts`). Ответ сети — подсказка, цифры вводит проверяющий. Новые размеченные цифры дописывайте в `real-digits.json` отдельной пачкой и переобучайте. Фото с именами учеников в git не кладём: образцы лежат в `scratch/omr-real` (не в git).
- «Пустое место» в билете: `question_id = null` и `snapshot.empty`. Код, читающий билеты, должен это учитывать.
- «Билеты классу»: **ключи ответов не отдавать ученику.** Снимок вопроса ученику собирает `publicSnapshot` по списку разрешённых полей (не «снимок минус ключи» — иначе новое поле утечёт); верные ответы (`reviewSnapshot`) отдаёт только действие `review` — когда попытка сдана и у запуска стоит `review_sent_at`. `review_send` работает только для закрытого запуска: пока ссылка открыта, разбор разослали бы тем, кто ещё пишет. Любое новое поле у ответа `tg-exam` проверяйте на это.
- «Билеты классу»: время решает **сервер**. Клиент получает `now` (часы сервера) и считает остаток по смещению (`serverOffset`); срок попытки, закрытие ссылки и автосдача проверяются в базе и функции по `now()`, а не по часам телефона.
- «Билеты классу»: ответ и сдача идут только через RPC `exam_attempt_save` и `exam_attempt_close` (один атомарный `update`, только `service_role`). Прямой `update exam_attempts` из функции вернёт гонку: два сохранения подряд теряли бы друг друга, а балл, посчитанный после сдачи, мог не совпасть с сохранёнными ответами.
- «Билеты классу»: ученики на сайте не входят, поэтому RLS на `exam_links` и `exam_attempts` для них закрыта полностью — их читает и пишет только `tg-exam` сервисным ключом (подпись Telegram проверяет `verifyInitData`). Ограничитель перебора кодов бота (`createMissLimiter`) хранится в памяти экземпляра функции: после перезапуска он пуст, это защита «по возможности», основная — 6 знаков из 31 и 10 промахов за 10 минут.
- «Билеты классу»: запускаются только обычные наборы — кластерные (`generation_params.source = 'cluster'`) отклоняет и `exam_link_create`, и интерфейс (`canLaunchBatch`).
- Анонимы не имеют прав на таблицы (`security_round4.sql`): новые таблицы для игры открывайте только через `security definer`-функции.
- Путь проекта на кириллице («генератор тестов»): в командах берите его в кавычки. Git предупреждает о CRLF, это нормально.

## 16. Эталонные данные по предметам

- **Право, открытые вопросы:** формат — условие «Определите…», шесть пунктов `1) … 6)` и инструкция «получится число»; `correct_numeric_answer` — цифры верных пунктов по возрастанию (1–4 цифры, четыре клетки в билете). В банке 319 таких вопросов (главы 1–5, по 5–7 на тему; задания ЦВЭ и экзаменов по темам уровней 6–10 лежат в главах 6–10, партия «Право: открытые вопросы (главы 1–5, RU+TJ)», источник «Учебник права, открытые вопросы (Часть N)»). Стандарт билета по праву — 20 тестов, 4 соответствия, 2 открытых (`STANDARDS` в `TicketGenerator.tsx`, `QUICK.law` в боте). Откат партии скрывает вопросы из банка.

- **Химия, расчётные задачи уровней 1,2,3,4 и 5:** эталонные единицы — литр (л) и грамм (г). В таких задачах не должно быть шагов перевода из одной единицы в другую (кг → г, л → мл и обратно): все величины в условии и в ответе даются сразу в л и г.
