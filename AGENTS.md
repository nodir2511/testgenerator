# Правила работы с репозиторием

## Обновления сайта («Что нового»)
Каждое изменение, заметное пользователям (новая функция, исправление, изменение интерфейса), должно сопровождаться записью в `supabase/sql/releases/YYYY-MM-DD_<версия>.sql`:
вызов `public.add_site_release(версия, заголовок, пункты, дата)`. Образец: `supabase/sql/releases/2026-10-14_0.2.0.sql`.

- У каждого пункта есть `min_rank` — кому он виден: `1` все, `2` админы по предметам и выше, `3` админы и выше, `4` только главный админ.
  Пункты про управление пользователями, статистику и т. п. делайте с `min_rank >= 3`.
- Текст пункта — одной фразой, понятной пользователю этого уровня, без технических деталей.
- Повышайте версию в `package.json` вместе с записью. Повторный запуск файла безопасен.
- Записи можно также вести через форму на вкладке «Что нового» (главный админ).

## Схема проекта
Перед работой прочитайте `docs/ARCHITECTURE.md`: там карта каталогов, модель данных, роли, главные потоки, правила деплоя и ловушки. Открывайте только те файлы, на которые она указывает, и не перечитывайте весь код.
Если вы меняете структуру (таблица, модуль, поток данных, ключ кэша, правило деплоя), обновите `docs/ARCHITECTURE.md` в том же коммите.
Перед выбором версии релиза сделайте `git fetch`: в `main` пушат параллельно, номера версий занимают быстро.
