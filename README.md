# Генератор экзаменационных билетов

Сайт для преподавателей: ведёт банк вопросов по предметам (тесты, задания на соответствие, открытые вопросы, на русском и таджикском), собирает из него экзаменационные билеты и выдаёт их в Word вместе с ключами ответов. Те же билеты можно получать через Telegram-бота и Telegram Mini App. Для главного администратора есть экзамен-кластер: тестовая книжка из нескольких предметов по образцу, плюс «Своя игра» для команд.

Фронтенд — React + TypeScript + Vite + Tailwind. Данные, вход и серверные функции — Supabase (Postgres и Edge Functions на Deno). Сайт публикуется на Vercel автоматически при пуше в `main`.

## Быстрый старт на новом компьютере

Нужны Git и Node.js 20 или новее.

```bash
git clone https://github.com/nodir2511/testgenerator.git
cd testgenerator
npm install
cp .env.example .env   # впишите значения Supabase (см. ниже)
npm run dev
```

Сайт откроется на адресе, который покажет Vite (обычно http://localhost:5173).

Значения для `.env` берутся в Supabase: Project Settings → API (`VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`). Остальные переменные из `.env.example` нужны только для импорта и Telegram, а секреты функций хранятся в самом Supabase. Файл `.env` в git не попадает, его нужно создать на каждом компьютере.

Проверка: `npm test` запускает тесты, `npm run build` — тесты, проверку типов и сборку.

## Работа с нескольких компьютеров

Код синхронизируется только через GitHub: перед работой `git pull`, после — `git commit` и `git push`. Папку проекта не нужно класть в Google Диск или другое облако: рядом с `.git` синхронизация портит репозиторий.

## Структура

```
src/                  Сайт
  components/         Экраны: генератор, банк вопросов, импорт, кластер, статистика…
  lib/                Экспорт в Word, ключи ответов, разбор документов, работа с базой
  tg/                 Telegram Mini App (страница /tg)
  game/               «Своя игра»
  hooks/, types/      Вход пользователя, типы данных
supabase/
  functions/          Edge Functions: бот, Mini App, управление пользователями
    _shared/          Общий код сайта и функций (подбор билетов, Word, ключи)
  sql/                SQL базы: схема, политики доступа, лимиты, функции
    releases/         Записи «Что нового» (по файлу на версию)
templates/key/        Шаблоны ключей ответов (исходники)
public/               Шаблоны ключей и картинки обложки кластера
scripts/              Служебные скрипты (синхронизация общего кода, сборка шаблонов)
tests/                Тесты (vitest)
```

Общий код в `supabase/functions/_shared/` частично генерируется скриптом `node scripts/sync-docx-shared.mjs` из `src/lib/`; правьте исходники в `src/lib/`, а не копии.

## Данные и файлы вне git

Сам банк вопросов лежит в базе Supabase, поэтому на новом компьютере его подключать не нужно: достаточно `.env`.

В git не попадают (см. `.gitignore`): `.env`, `node_modules`, `dist`, папка `scratch/` с рабочими скриптами и исходными подборками (около 44 МБ), любые `.docx` и `.zip`, кроме шаблонов ключей, и SQL-файлы импорта данных. Если эти исходники нужны на другом компьютере, храните их на Google Диске и копируйте вручную в те же папки (`scratch/`, `temp_docs/`).

## Обновления сайта

Каждое заметное пользователям изменение сопровождается записью в `supabase/sql/releases/` и повышением версии в `package.json`. Подробности — в `CLAUDE.md`.

## Деплой

- Сайт: пуш в `main`, Vercel собирает и публикует сам.
- SQL: `npx supabase db query --linked -f supabase/sql/<файл>.sql`.
- Функции: `npx supabase functions deploy <имя> --project-ref <ref>` (для `telegram-bot` и `tg-app` добавьте `--no-verify-jwt`). Нужен `npx supabase login` и привязка проекта (`supabase link`).
  Без CLI (например, через Supabase MCP): деплоится файл-обёртка из одной строки
  `import 'https://raw.githubusercontent.com/nodir2511/testgenerator/<коммит>/supabase/functions/<имя>/index.ts';` —
  Supabase сам скачивает при сборке функцию и общие модули `_shared` на этом коммите. Коммит должен быть уже в GitHub;
  откат — та же обёртка с прошлым коммитом.
