# План реализации: Комплексная модернизация системы проверки бланков (OMR)

Данный план описывает техническую реализацию улучшений модуля проверки бланков ответов в Donishmand Platform / Генераторе тестов.

---

## 1. Обзор целей и задач

1. **Строгое распознавание отметок**:
   * Повышение порога `FILL_ON` до 0.40–0.42 (засчитывать только плотную закраску кружка; крестики, галочки и случайные черкания отсекать).
2. **Устойчивость к геометрии и условиям съемки**:
   * Определение отсутствующего угла при нахождении 3 из 4 маркеров с выводом точной подсказки пользователю.
   * Локальное адаптивное выравнивание сетки (Local Grid Refinement) для компенсации изгибов и замятия бумаги.
3. **Качественный скачок в распознавании рукописных цифр**:
   * Удаление типографской рамки клетки (Border Clearing) перед анализом цифры.
   * Внедрение автономной микро-нейросети прямо в JS (Tiny Neural Network, ~20 КБ, без внешних библиотек) взамен/в дополнение к kNN.
4. **Удобство преподавателя и экспорт**:
   * Выгрузка сводной ведомости результатов проверки пачки в Excel (`.xlsx`) через уже имеющуюся библиотеку `write-excel-file`.
   * Режим «Живой видоискатель» (WebRTC / `getUserMedia`) с оверлеем рамки бланка и автоматическим переходом на стандартную камеру при отсутствии поддержки WebRTC в Telegram WebView.

---

## 2. Поэтапный план реализации

### Фаза 1: Улучшение детекции меток и подсказка маркеров (OMR Core)
* **Файлы**: `src/lib/omr/recognize.ts`, `src/lib/omr/types.ts`, `tests/omr.test.ts`.
* **Задачи**:
  1. **Поднятие порога `FILL_ON`**: скорректировать порог с `0.38` до `0.40–0.42`. Проверить, что одиночные тонкие штрихи отсекаются, а качественная закраска распознается со 100% точностью.
  2. **Детекция 3 из 4 маркеров**:
     * Если алгоритм находит три согласованных угла (например, TL, TR, BL), то по геометрическим соотношениям бланка восстанавливать теоретическую позицию 4-го угла (BR).
     * В случае неудачи локализации возвращать в `OmrFail` или `OmrResult` поле `missingCorner: 'TL' | 'TR' | 'BL' | 'BR'`.
     * В UI формировать понятное сообщение: *«Не виден нижний правый угол — уберите пальцы или расправьте край бланка»*.
  3. **Локальное выравнивание сетки (Grid Refinement)**:
     * Для бланков с лёгким изгибом проводить микро-подстройку вертикального шага строк по фактическим центрам напечатанных контуров кружков (`ringScore`).
* **Верификация**: запуск тестов `npx vitest run tests/omr.test.ts`.

---

### Фаза 2: Очистка рамок ячеек (Border Clearing) и микро-нейросеть для цифр
* **Файлы**: `src/lib/omr/digits.ts`, `src/lib/omr/digitNn.ts` (новый), `src/lib/omr/model.ts`, `scripts/train-digit-nn.mjs` (скрипт сборки весов), `tests/omrDigits.test.ts`.
* **Задачи**:
  1. **Border Clearing (`cleanBoxBorders`)**:
     * В `openBox` перед формированием битовой маски сканировать контур ячейки. Связные компоненты чернил, непрерывно идущие вдоль наружной рамки ячейки (типографская печать рамки), занулять.
     * За счёт этого цифры, написанные вплотную к рамке, не склеиваются с ней и не превращаются в ложные единицы.
  2. **Архитектура микро-нейросети**:
     * Вход: нормализованное изображение $14 \times 14$ пикселей (196 значений $0..1$).
     * Архитектура: двухслойный полносвязный перцептрон (196 $\to$ 64 $\to$ 10) с функцией активации ReLU и Softmax на выходе.
     * Размер матрицы весов: $(196 \times 64 + 64) + (64 \times 10 + 10) = 13\,258$ чисел $\approx 14$ КБ в формате Int8/Float32.
     * Код инференса в [src/lib/omr/digitNn.ts](file:///c:/Users/nodir/Desktop/генератор%20тестов/src/lib/omr/digitNn.ts): 40 строк чистого TypeScript без зависимостей, время расчета $< 1$ мс.
  3. **Генератор весов (`scripts/train-digit-nn.mjs`)**:
     * Скрипт, обучающий модель на расширенной синтетической выборке + накопленных в базе реальных образцах цифр.
     * Экспорт весов в компактный TS-модуль `digitWeights.generated.ts`.
  4. **Интеграция в `model.ts`**:
     * `guessOpen` использует предсказания нейросети, с проверкой уверенности (порог вероятности Softmax $> 0.70$).
* **Верификация**: запуск тестов `npx vitest run tests/omrDigits.test.ts`.

### Фаза 3: Выгрузка ведомости проверки в Excel (`.xlsx`)
* **Файлы**: `src/lib/omr/exportExcel.ts` (новый), `src/tg/CheckScreen.tsx`.
* **Задачи**:

     * Стилизация таблицы: шапка с фирменным стилем, авто-ширина колонок, форматирование процентов и чисел.
  2. В интерфейс [src/tg/CheckScreen.tsx](file:///c:/Users/nodir/Desktop/генератор%20тестов/src/tg/CheckScreen.tsx) (экран `Results` и завершение проверки стопки):
     * Добавить кнопку **«📥 Скачать ведомость в Excel»** (работает как скачивание файла в браузере или отправка файла через бота в чат Telegram).
* **Верификация**: проверка создания Excel-файла и выгрузки тестовой пачки.

### Фаза 4: Улучшение процесса съемки (Видоискатель и UI)
* **Файлы**: `src/tg/CheckScreen.tsx`, `src/tg/tg.css`.
* **Задачи**:
  1. Создать компонент видоискателя `LiveCameraModal`:
     * Запуск потока камеры через `navigator.mediaDevices.getUserMedia({ video: { facingMode: 'environment', width: { ideal: 1920 } } })`.
     * Полупрозрачный оверлей (рамка формата полоски бланка $1:2.5$ с четырьмя угловыми видоискателями).
     * Кнопка быстрого снимка (Capture) с передачей кадра напрямую в OMR-конвейер.
  2. Защитный Fallback:
     * Если WebView Telegram блокирует доступ к камере или пользователь отказал в разрешении, интерфейс плавно и бесшовно переключается на нативный выбор файла `<input type="file" capture="environment">`.
  3. Отображение подсказок ошибок в UI:
     * Вывод подсказок по отсутствующим маркерам (например: *«Не виден нижний угол»*).

4. Отчет по проверенной стопке корректно выгружается в Excel.
5. Зафиксированы и обновлены все сопутствующие документы (включая `docs/ARCHITECTURE.md`).
