# План реализации: Заполнение недостающих заданий формата НЦТ из банка («наши билеты по типу»)

Пользователь столкнулся с ошибкой:
> «Формат НЦТ: В выбранных темах нет тестов из разделов НЦТ»
> «Не удалось сгенерировать билеты. В выбранных темах нет вопросов для формата НЦТ»

**Требование пользователя**:
> «Если не хватает билетов НЦТ то бери наши билеты подходящие по типу»

---

## 1. Анализ проблемы

1. **Почему возникала ошибка**:
   * В режиме НЦТ планировщик `planNct` рассчитывает раскладку заданий (например, для истории: 20 тестов, 4 соответствия, 2 открытых).
   * Ограничения `kindRange` (например, в истории для раздела 1: от 3 до 7 тестов) и `maxPerSection` (открытые: не более 1 на раздел) были рассчитаны **только на полный экзамен** (когда выбраны все 4 раздела).
   * Если пользователь выбирает только 1 главу (например, Глава 1 истории) или несколько тем, раздел `p1` физически не может выдать 20 тестов из-за жёсткого ограничения `cap = 7`, а открытые не могут набрать 2 штуки из-за ограничения `max = 1`.
   * В результате `planNct` возвращает `null`, `pickNct` возвращает 0 заданий, и генератор выбрасывает ошибку: *«В выбранных темах нет вопросов для формата НЦТ»*, хотя в Главе 1 в базе есть 659 тестов, 114 соответствий и 61 открытый вопрос!
   * Кроме того, если в выбранных темах мало официальных вопросов ЦВЭ или мало размеченных типов, `pickNct` мог набрать меньше заданий, чем нужно по стандарту билета.

2. **Как должно работать по требованию пользователя**:
   * Если выбрана часть тем/глав: режим НЦТ не должен блокироваться искусственными лимитами полного билета — доступные разделы должны заполнять билет полностью.
   * Если официальных заданий НЦТ (`isNct`) или заданий нужной сложности/типа не хватает, чтобы заполнить все слоты билета:
     генератор должен брать **наши вопросы из банка** (`allQuestionsRaw`), подходящие по типу (`test` $\to$ тест, `matching` $\to$ соответствие, `open` $\to$ открытое).
   * Если в темах вообще нет специфической разметки НЦТ: билеты формируются из вопросов банка с сохранением структуры билета НЦТ (например, 20 тестов + 4 соответствия + 2 открытых для истории/права; 18 + 2 + 7 для химии/математики).

## 2. Предлагаемые изменения

### Файл 1: `supabase/functions/_shared/nct.ts`
1. **Гибкость `planNct` при выборе подмножества тем (`isSubset`)**:
   * Если `present.length < SECTION_KEYS.length`: не применять верхние границы `kindRange` и `maxPerSection`, которые были рассчитаны на полный охват всех разделов, позволяя выбранным разделам набрать полный состав билета (`composition`).
2. **Мягкий fallback в `pickNct`**:
   * Если темы не попали в официальную карту разделов (`present.length === 0`), но в пуле есть вопросы (`pool.length > 0`): относить их к первому разделу предмета с понятной заметкой пользователю, а не сбрасывать в 0.
   * В `pickOne`: если по отдельным уровням сложности (1, 2, 3) не набирается $T$ одинаковых вопросов, брать любые доступные свободные вопросы этого типа (`free`).
   * В `attempt`: если не удаётся набрать по метке типа или фильтру свежести тем, брать любые вопросы пула нужного типа (`kind`).

### Файл 2: `src/components/TicketGenerator.tsx`
1. **Добор недостающих заданий из банка («наши вопросы по типу»)**:
   * В блоке `if (nct)` после вызова `pickNct`:
     * Проверить количество набранных заданий каждого типа (`test`, `matching`, `open`).
     * Если по какому-либо типу набрано меньше, чем требует стандарт (`composition`):
       выбрать недостающее число заданий из обычного пула `allQuestionsRaw` (наши вопросы) через `pickParallel`.
     * Если `pickNct` не смог подобрать вообще ничего (0 заданий):
       взять билеты из стандартного `picked` (который уже сгенерирован строкой выше из наших вопросов с нужными пропорциями) и показать мягкое уведомление: *«В выбранных темах недостаточно заданий формата НЦТ — билеты составлены из вопросов банка по типу»*.
   * Исключить падение с ошибкой *«В выбранных темах нет вопросов для формата НЦТ»*, если в темах есть подходящие вопросы нужных видов.

### Файл 3: Тесты (`tests/nct.test.ts`, `tests/nctHistory.test.ts`)
1. Тест: генерация билета формата НЦТ по Истории при выборе **только Главы 1** (раздел `p1` набирает 20 тестов, 4 соответствия, 2 открытых без ошибок).
2. Тест: добор вопросов при нехватке официальных заданий НЦТ (добор из обычного пула).
3. Прогон всего набора тестов (`npx vitest run`).

---

## 3. Критерии приемки (DoD)
1. При выборе любой одной главы или набора тем (в Истории, Химии, Математике, Праве) с включённым режимом НЦТ билеты успешно формируются.
2. Билеты содержат ровно требуемый состав (например, 20 + 4 + 2 для истории).
3. Если заданий НЦТ не хватает, слоты заполняются нашими вопросами из банка подходящего типа.
4. Нет блокирующих всплывающих ошибок «Не удалось сгенерировать билеты».
5. Все тесты (`npx vitest run`) проходят (354+ тестов).
